# Public demo assets

All files under `site/assets/` in this edition are project-created assets or data describing project-created geometry. They are covered by the root MIT license. Individual file hashes, sizes and roles are recorded in `assets-manifest.json`.

| Asset group | Source |
| --- | --- |
| `scene/*.webp`, `worlds/ghostblade/base*.webp`, empty desk patches | Original parametric desk rendered by `blender/render_demo.py` and encoded by `scripts/package-renders.py` |
| Wall labels, wallpapers, covers, decal and icon | Original code-drawn geometric graphics from `scripts/generate-demo-assets.py` |
| `audio/room-tone.wav` | Original additive synthesis from the same script; no sampled/commercial sound recording |
| `collectibles/models/orbit.glb` | Original rings/sphere/stand sculpture generated by `blender/render_demo.py` |
| `turntable/hao-turntable.glb` | Project-created parametric DJ turntable, exported from the geometry in `blender/desk_revision.py` |
| `books/窗外最后一班车.txt` | Original demonstration story written for this project |
| Hotspot / camera / surface JSON and masks | Projection data for the original desk geometry; includes legacy internal identifiers |
| `worlds/ghostblade/room-environment.hdr` | Original mathematical sky/ground gradient, not a downloaded HDRI |

The offline source code uses the MIT helper in `blender/kit.py`; preserve its original notice.

## Optional rebuilding

For the already committed artwork, none of these tools are needed. To regenerate the demo texture set and backdrops, use Python 3.10+, Pillow and Blender 4.5:

```sh
python -m pip install Pillow
python scripts/generate-demo-assets.py
blender -b -t 8 -P blender/render_demo.py -- --width 2560 --samples 24
python scripts/package-renders.py
node scripts/asset-manifest.mjs
```

If Blender is not on PATH, replace `blender` with the path to your Blender executable. CUDA/OptiX is optional; CPU rendering is supported but slower. System fonts are selected locally; no font files are redistributed. Exact rasterization and lighting may vary slightly between platforms and Blender versions.

The camera and desk layout deliberately match the committed picking/projection metadata. Moving objects or the camera requires updating that metadata as well, not only re-rendering the image. The pre-rendered desk and runtime plant/book/sculpture layers are separate so visitors can interact with each object.

`blender/textures/`, `.blend` files and `.local/` render intermediates are generated work files and ignored by Git. Browser-ready outputs under `site/assets/` are committed so a fresh clone works offline after the local server starts.
